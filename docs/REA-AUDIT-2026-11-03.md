# REA audit, 2026-11-03 (ulyOS v1.19.0)

Tool: REA 6.8.0 (`rea analyze-javascript-application`) plus direct cross-checks.

## 1. Published site vs repository
- Downloaded all 61 files of the offline manifest (`js/config.js` FILES) plus `sw.js` from https://ulyweb.github.io/ulyOS/ and compared SHA-256 with the repo: **62 of 62 identical**.
- REA on the live copy: 55 files, 35 JavaScript files parsed, 0 parse failures, 0 integrity contradictions.
- No `eval`, `new Function` or `document.write` in first-party code or the converted apps.
- Every `fetch` / `WebSocket` in first-party code and apps goes to a host in the CSP `connect-src` (or to the same origin / `/__ping` for the offline server).
- CSP notes (by design, documented): `script-src 'self'`; `style-src` still has `'unsafe-inline'`; `img-src` and `frame-src` allow `https:` (hotlinked photos, App Store frames). Third-party frames are sandboxed.
- REA's static endpoint extraction only sees literal strings, so it found 1 of the ~13 allowed hosts. Treat it as a second opinion, not a complete network inventory.

## 2. Vendored libraries and converted apps
- `vendor/jsQR.js` = npm `jsqr@1.4.0` dist (identical SHA-256).
- `vendor/qrcode.js` = npm `qrcode-generator@2.0.4` dist (identical).
- `vendor/lamejs.min.js` = npm `@breezystack/lamejs@1.2.7` `dist/lamejs.iife.js` (identical).
- `vendor/espeak/*` (13 files) = npm `mespeak@2.0.2` config and voices (identical).
- `vendor/mespeak.js` = npm `ESpeak.js` + `index.js` in a wrapper; same code, differing only in line endings and Latin-1 to UTF-8 encoding of comments.
- REA on `vendor/` and `apps/`: 0 parse failures, 0 contradictions. The apps' only network calls are CoinGecko prices (Crypto Compass) and the disclosed contact endpoint.
- Note: Crypto Compass contains referral links (Robinhood, Tangem promo code, Uphold). Informational; consider a visible disclosure.
